## 1. 执行规则

每个阶段依次完成下列动作：

1. 核对前置验收和工作区，保留用户已有修改；在功能分支中进行，不污染现有正式交付。
2. 按本阶段步骤实现一个可运行增量，新增必要的边界/集成回归，不为简单属性重复堆测试。
3. 运行相关测试与架构检查，再执行必要的目标平台人工验收。
4. 检查差异、文件与数据库状态，写验收结果和未执行原因；通过后独立提交。
5. 更新阶段状态与下一步；常规后续工作连续推进，不为每个小步骤重复询问许可。

阶段未通过不得把相关功能标完成；可以处理独立工作，但不能越过依赖链发布。必须依赖 Windows/Key 的项目未满足时标阻塞，不模拟通过。

验收结果字段统一为：用例 ID、对应提交、环境/样本摘要、实际步骤、预期、实际结果、状态、证据路径、缺陷编号。每阶段至少输出 `docs/evidence/reader/Pn/acceptance.md`。

## 3. P0：可重现基线与隔离环境

目标：知道“从什么版本开始、旧功能现在是否通过、样本与数据如何隔离”。

步骤：

1. 记录 HEAD、工作区修改、远端 main 查询结果，保留现有 v1 交付；建立 reader 功能分支，不覆盖用户文档。
2. 检查 SDK 8.0.424/兼容补丁、NuGet 和桌面依赖；当前会话尚未发现 dotnet，实际实施时安装/配置后再继续。
3. 在 Code 运行锁定还原、Release 构建、现有全量测试；记录当时用例数量，不能固定写死 94。
4. 用 READJOURNAL_DATA_DIR 指向隔离目录运行；制作包含旧书、阅读记录、书摘、计划和多个历史完成计划的 schema 1 数据库及 JSON fixtures。
5. 创建可重复样本生成器：中文/英文混排、百万字 TXT、极长段落、emoji/组合字符、CRLF/LF、UTF-8 BOM/无 BOM、GB18030、自建小 EPUB。
6. 记录目标 Windows 机器配置和字体/DPI；无法访问时把 Windows 项明确挂起。

基础命令在 Code 下执行：

```sh
dotnet restore ReadJournal.sln --locked-mode
dotnet build ReadJournal.sln -c Release --no-restore
dotnet test ReadJournal.sln -c Release --no-build --no-restore --logger trx
```

新增依赖时有意识更新锁文件，再恢复 locked-mode；不要通过长期去掉锁定来掩盖依赖问题。

| 用例 | 验收 |
|---|---|
| P0-01 | 干净源码可还原/构建；失败能定位为环境或代码问题，修复后完整基线通过 |
| P0-02 | 隔离库实际启动，正常关闭；真实默认数据目录不被写入 |
| P0-03 | schema 1/JSON fixtures 可被当前版本读取，字段/行数/摘要被记录 |
| P0-04 | 自建样本重复生成摘要一致，大文本不进入正式源码 ZIP |

产物：环境说明、基线 TRX、旧库/JSON fixtures、样本生成器、功能分支基线提交。

停止条件：旧功能基线失败或数据未隔离时，先解决，不进入 P1。无 API。

## 4. P1：原生分页与文字选择可行性

目标：验证主要技术风险，暂不接入业务数据库或导入入口。

步骤：

1. 用最小实验工程/隔离页面读取合成规范化 TXT，只支持一个阅读视口和少量控件。
2. 实现布局参数、正文范围、前后翻页与上下章衔接，记录每页覆盖范围。
3. 验证只读 TextBox 是否能与 TextLayout 边界完全一致；不能一致时改用统一 ReaderSurface，并记录选择原因。
4. 实现命中、拖动选区、复制；验证字形位置与 UTF-16 原文范围映射。
5. 改字号、字体、行距、窗口和 DPI，取消旧布局并按原锚点定位。
6. 按章/块渐进排版，后台索引全书页数，支持取消；测量翻页/重排/首屏和内存。
7. 依据目标机器记录定版缓存/内存预算；不把实验对象直接塞进现有 VM 全局单例。

| 用例 | 验收 |
|---|---|
| P1-01 | 拼接所有页面正文映射等于规范化原文，无漏字、重复、断开代理对 |
| P1-02 | 中文、英文、段首缩进、标点、空行、单个超长段落、emoji/组合字符均无越界和死循环 |
| P1-03 | 拖选/复制内容与文档范围一致，反向拖动和页边界选择不产生错误偏移 |
| P1-04 | 反复改变字体/字号/视口后可找到同一正文锚点，不靠原页号恢复 |
| P1-05 | 百万字样本不要求整本分页后才出首屏；旧后台任务取消后不覆盖新页面 |
| P1-06 | 同一机器预热翻页 200 次 P95≤100ms，视口重排 P95≤500ms；首屏目标≤2s；记录原始数据和冷/热口径 |
| P1-07 | 100%/150%/200% Windows DPI、中文字体回退、键盘焦点行为通过实机验证 |
| P1-08 | 全书页数未完成时显示计算中；已知页范围可解析，取消不锁住界面 |

产物：实验提交、布局/选区算法说明、样本/性能记录、截图、通过/失败结论。

停止条件：漏字/选区错位未修复或性能门槛未达标，不进入数据集成。若原生方案需改变，先用实验证据说明具体阻塞，再与用户讨论。无 API。

## 5. P2：正式契约、兼容读模型与 schema 2

目标：一次确定数据语义和跨层接口，保护旧数据。

步骤：

1. 按接口文件创建模型和核心接口；将 P1 布局实现迁入 UI，将无 UI 类型契约放 Library。
2. 创建统一状态计算器，覆盖 Manual/Ebook、HasStarted/CompletedAt/可回退位置的规则；扩展 BookProgress/PlanItem，保留旧方法兼容。
3. 添加 ApplicationDataCoordinator、同目录单实例锁与 DataEpoch；实现实例/维护/正常操作的顺序。
4. 实现 DatabaseMigrationV2，包含 BookUid、Kind、Quote.Revision、全部新表/键/索引及 AppMetadata。
5. 新增服务 DI 注册骨架，验证容器无循环；生产导入/Reader 入口仍关闭，数据库中只使用合成电子书 fixture。
6. 明确旧 JSON DTO → 新 DTO 规则，统一实体校验器供存储和备份共用。

| 用例 | 验收 |
|---|---|
| P2-01 | 真实旧库迁移后旧行主键、文本、时间、页码和关联一致；user_version=2，完整性与外键通过 |
| P2-02 | 迁移中断/SQL 失败全部回滚，重试成功；schema 高于支持值时明确拒绝 |
| P2-03 | 每个旧 Book 得到独立非空 BookUid，Kind=Manual；旧 Quote.Revision=0 |
| P2-04 | Ebook 允许 TotalPages=0，Manual 仍拒绝；禁止电子书手动页码记录和跨种类转换 |
| P2-05 | 电子书未开始/在读/已完成逻辑不依赖 0/0 页；完成后回看保持状态；重置检查历史计划冲突 |
| P2-06 | 新服务从真实容器解析，单例映射正确，Library 无 Avalonia 引用；数据库服务不重入 |
| P2-07 | 第二进程不能写同一目录；维护期间旧 epoch 写入被拒绝，Reader 注册与维护互斥 |

产物：契约代码、迁移、状态计算器和回归、数据库 fixtures、DI/架构记录。

停止条件：旧数据差异或备份输入语义未明确，不启用电子书。无 API。

## 6. P3：完整备份、恢复与中断修复

目标：真实电子书导入前，具备恢复原书与关联数据的能力。

步骤：

1. 实现完整 ZIP v2 manifest/data DTO/文件清单，使用合成受管文件与 canonical fixture。
2. 导出在维护权下取得一致快照；先写临时 ZIP，校验后同卷完成路径替换，失败不留下“完成”的损坏包。
3. 实现安全验证、旧 JSON v1 适配、恢复前完整自动备份。
4. 实现 RestoreId、日志、staging/trash 与数据库 LastRestoreId 提交协议；启动主业务前完成对账。
5. 改造现有 BackupService 外观、设置页选择器与说明；恢复旧 JSON 明确整体替换电子书数据。
6. 向导入/恢复/删除公共文件层注入故障点；分别模拟文件、数据库、日志写入失败和进程中断。

| 用例 | 验收 |
|---|---|
| P3-01 | 包含旧实体、新表、原书、canonical 与资源的备份往返，业务字段和文件 SHA-256 一致 |
| P3-02 | 旧 JSON v1 可恢复为 Manual；当前电子书整体替换前生成可读完整自动备份 |
| P3-03 | 缺文件、摘要错误、重复 ID、孤立关联、超限 ZIP、越界路径/绝对路径均在改数据前拒绝 |
| P3-04 | 自动备份失败则恢复零写入；目标文件安装失败不改数据库 |
| P3-05 | 在旧目录隔离、目标安装、数据库事务中、事务后收尾四类点强制中断，重启恢复为完整旧集或完整新集 |
| P3-06 | 不包含 Key/secure/日志/staging/布局缓存；恢复保留本机主题和 Key |
| P3-07 | 恢复更新 DataEpoch 并清理单例旧内容；旧整数 Id/BookUid 响应不能回写 |
| P3-08 | 日志不足以自动恢复时停止主业务并保留两套数据，诊断明确；不能静默清空 |

产物：完整备份服务、旧格式适配、恢复日志与对账、故障注入记录、ZIP fixtures。

停止条件：任一可恢复性用例失败，不开启真实导入。无 API。

## 7. P4：受管 TXT 导入、扫描与书库

目标：让真实文件安全进入统一书库，所有 Ready 条目可验证且可备份。

步骤：

1. 实现 TxtBookParser、编码和规范化规则，流式读/分块写 canonical。
2. 实现受限 staging 导入和 SHA-256 去重，文件就绪后一次数据库提交。
3. 接入新文件选择器；导入按钮、进度、重复/失败结果与书架刷新。
4. 实现根目录扫描、变化文件跳过和显式刷新；启动先恢复操作日志，再扫描。
5. 实现文件缺失标记、统一删除、trash 清理；保留全部来源文件。
6. 用实际导入生成的 TXT 做完整备份/删除/恢复，追加 P3 真实链路验收。

| 用例 | 验收 |
|---|---|
| P4-01 | UTF-8 BOM/无 BOM、GB18030 明确指定、换行混合可正确读取；非法编码不静默损坏原文 |
| P4-02 | 无章节标题和极长段落仍可分块；canonical 摘要稳定，块边界不漏字 |
| P4-03 | 外部源和收件源字节摘要不变；重复文件只产生一本，同名不同内容产生不同书 |
| P4-04 | 并发导入相同内容由数据库唯一键保护，另一导入返回 Duplicate，无孤儿目录 |
| P4-05 | 复制、解析、移动、事务前后中断均能在启动对账中收尾；不出现可见但无文件的 Ready 书 |
| P4-06 | 扫描不递归 managed，反复刷新不重复；正在变化的收件文件暂缓，一个损坏文件不阻断其他书 |
| P4-07 | 删除确认计数包含会话与文件，数据库关联删除；外部源保留；清理失败有日志可重试 |
| P4-08 | 新导入 TXT 完整备份后删除再恢复，正文/元数据/初始进度一致；Missing 明确提示 |

产物：导入服务、TXT 解析器、书库 UI、扫描/删除/对账、真实往返证据。

停止条件：Ready 文件不完整、来源被改动或重复行未解决，不继续 Reader 正式接入。无 API。

## 8. P5：正式 Reader、续读、正常退出会话

1. 新 ReaderView/ReaderViewModel、ServiceLocator 属性、内容路由和 ReaderOpenRequest。
2. 将 MainViewModel 异步离开协调统一用于菜单/返回/直接内容跳转/切书/关窗，保留原内容栈。
3. 接入 P1 布局、目录、键盘/按钮、全屏与阅读偏好；最后位置是正文锚点。
4. 首屏成功后 Begin；正常离开冻结终点，一次事务保存 Session 和 Progress；添加 CloseFailed 重试/继续行为。
5. 分开 IsBusy/IsLayoutBusy/IsAiBusy，清理旧任务和缓存，建立完整上下文身份。
6. 增加临时基础历史展示，完整统一列表于 P6 完成；此时已能查询自动会话确认保存。

| 用例 | 验收 |

1. 核验并锁定 EPUB/HTML 解析依赖及许可证；只通过适配器使用供应商 API。
2. 实现 ZIP/container/OPF/spine/目录解析；按阅读顺序提取正文。
3. 规范化基本标题、段落、粗斜体和本地图片；图片等比缩放、不溢出视口。
4. 为 spine、章节、块与资源生成稳定键和摘要；保留解析警告与格式不支持原因。
5. 禁止脚本、外部实体、远程图片和相对路径越界；限额防异常包拖垮应用。
6. 用不少于 10 本约定的文字类 EPUB 验收，至少包含 5 个可复现自建变体；不足真实样本时报告覆盖限制，不伪造兼容率。

| 用例 | 验收 |
|---|---|
| P7-01 | spine 与目录顺序不同、同名章节、嵌套目录均按正确正文顺序阅读 |
| P7-02 | 基本文字样式、中文标点和图片正常；图片大于视口可缩放分页，选区不会含占位伪原文 |
| P7-03 | 跳章、改字号、退出重开、选区书摘与回跳精确，完成/会话规则与 TXT 相同 |
| P7-04 | 缺资源、损坏 XHTML/ZIP、DRM/固定布局给明确结果；安全拒绝外部路径/资源/超限内容 |
| P7-05 | EPUB 完整备份恢复包含源、canonical 和图片，位置/书摘仍可回跳 |
| P7-06 | TXT 和旧手动业务回归通过；兼容清单逐本记录支持/降级/拒绝及原因 |

产物：EPUB 适配器、图片/样式映射、样本兼容表、M2 可运行提交。

停止条件：正文缺失、顺序错误、锚点失效或资源越界未解决，不宣布 EPUB 完成。无 DeepSeek API；依赖还原网络与内容 API 是不同事项。

## 11. P8：AI 本地流程、Mock 与安全配置

目标：在不上传正文、不花真实 API 费用的条件下完成 AI 业务正确性。

步骤：

1. 实现配置/密钥接口、设置页隐藏输入和删除；测试使用虚构 Key，禁止输出真实凭据。
2. 实现当前页/选区/全书页范围的 AiScopeSnapshot；页索引未就绪等待并允许取消。
3. 实现 DeepSeek HTTP 适配与 MockHandler，所有验收默认 Mock，不联真实服务。
4. 实现结构化候选解析、本地精确匹配与消歧、拒绝规则和程序锚点。
5. 实现批次自动保存/去重/安全撤销；生成前界面清楚说明会自动入库。
6. 实现取消、过期响应、DataEpoch、输入/输出限额和错误提示；AI 状态独立于阅读忙态。

| 用例 | 验收 |
|---|---|
| P8-01 | 请求体只含冻结范围，未包含前后未选章节；重排使待选页号失效，已提交快照不变 |
| P8-02 | 页范围未就绪时 HTTP 请求计数为 0；取消解析/取消 AI 不新增记录 |
| P8-03 | 分析/解释不写 Quote；合法书摘通过原句校验自动入库，BookUid/范围正确 |
| P8-04 | 伪造原句、范围外真实原句、重复句无法消歧、跨图片拼接、无效 JSON/超大响应均不作为合法原文保存 |
| P8-05 | 部分合法候选只保存合法项并列明拒绝/重复数量；批次同成同败，保存重试不重发 API |
| P8-06 | 同 BatchId 重试幂等；撤销只删本批未修改新增项，保留用户修改/收藏项及原先已存在书摘；重复撤销幂等 |
| P8-07 | 401/403/429/5xx/离线/超时/断流/取消均有对应提示，本地翻页和正常退出可用 |
| P8-08 | 请求发出后切书/返回/恢复/复用同 Id，旧结果零写入、不改新面板 |
| P8-09 | 密钥只在平台保护存储或会话内；备份、日志、截图、异常、仓库搜索均无测试凭据明文泄漏 |
| P8-10 | 输入超限/并发第二请求被限制；超时不自动重发可能已计费请求；费用无可靠依据时仅标估算 |

产物：AI 服务与 Mock 回归、凭据适配、批次/撤销、待真实联调清单。

停止条件：原文伪造可入库、过期响应可写或 Key 泄漏，禁止 P9。此阶段不需要真实 Key。

## 12. P9：真实 DeepSeek API 联调

目标：在受控范围验证供应商当前接口与实际业务效果。

步骤：

1. 向用户通知已完成的本地/Mock 验收、真实 API 需求、拟发送文本和本轮最大调用次数；明确可能计费。
2. 用户在应用设置页安全输入 Key；不在聊天或仓库接收明文。检查当前网络策略是否允许官方 endpoint，拒绝时通过受支持配置流程解决，不绕过限制。
3. 核验官方当前 endpoint、可用 model、认证、结构化输出能力、费用与输出限制，记录链接和查询日期。
4. 用合成无敏感短文执行最小联通，再测试当前页分析、选区解释和书摘提取。范围测试尽量沿用 Mock 证据，不为覆盖每个错误制造计费请求。
5. 检查原文匹配率/拒绝原因、耗时、实际 usage（若供应商提供）、可取消性及 UI 提示。
6. 删除测试 Key 后验证缺凭据提示；真实失败保留清楚错误，阅读仍可离线。

| 用例 | 验收 |
|---|---|
| P9-01 | 用户已获 API 通知并完成应用内配置/正文发送知情步骤，真实调用使用已核验模型 |
| P9-02 | 短文分析与选区解释实际成功，返回显示但不默认入库 |
| P9-03 | 自动书摘实际返回后，逐条本地核验、自动保存、定位与撤销通过 |
| P9-04 | 大范围按上限处理，未偷偷上传整书；日志无 Key/全文，真实 usage 与估算区分 |
| P9-05 | 实际断网/取消/删除凭据时提示清楚，本地阅读与会话仍正常；不自动重试计费请求 |

产物：不含正文与 Key 的真实联调记录、当前供应商配置依据、M3 功能验收。

停止条件：缺 Key、网络不允许或供应商不可用时标真实联调阻塞，继续独立发布文档与本地修复；不得以 Mock 冒充。本轮规划编制不执行此阶段。

## 13. P10：Windows 发布验收与独立源码包

目标：最终功能在目标机器可使用，交付版本与证据配对。

步骤：

1. 当前源码全量锁定还原、Release 构建、全部相关测试；真实容器/架构/导航探针同步更新 Reader 和新增单例。
2. Windows 实机执行全功能闭环和 DPI/全屏/输入/文件选择器/凭据验证；其他平台按实际验证范围记录。
3. 大文件性能、连续切书内存、长任务取消、异常文件、导入/恢复中断重启集中回归。
4. 扫描日志/备份/源码中的凭据和错误正文，检查离线阅读无意外请求。
5. 更新 README、已知边界、数据目录与备份说明、依赖许可证、delivery-files.txt 和 pack.py 白名单。
6. 独立新目录解包源码，锁定还原/构建/测试/隔离启动，确认不依赖开发目录或本机私有路径。
7. 验证源码包不含 bin/obj/运行库/Key/大样本且不超过课程 10MB 要求；正式报告若本轮后续要求更新，则使用当前正式 Word 作为底稿另行生成，不能自动覆盖旧报告。

| 用例 | 验收 |
|---|---|
| P10-01 | 当前全量与干净包测试通过，数量/提交/环境准确，所有新增文件在白名单 |
| P10-02 | 新库和迁移库均通过 TXT/EPUB→会话→书摘→计划统计→完整备份恢复→重启闭环 |

| P10-06 | 源码 ZIP≤10MB、无编译结果/运行数据/凭据，README 与实际功能/版本/证据一致 |
