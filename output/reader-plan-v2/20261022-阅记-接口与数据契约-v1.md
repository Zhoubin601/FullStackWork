# 阅记：接口与数据契约 v1

日期：2026-10-22。配套：[总体规划 v2](20261022-阅记-原生阅读器与AI助手-完整实施规划-v2.md)。

本文件为拟实施契约，示例 C# 类型应在对应阶段创建并经过实际编译；不表示当前仓库已有这些接口。现有接口兼容方式见第 8 节。类型名可以在实施时作不改变语义的整理，跨阶段契约变化必须同步文档和调用方。

## 1. 全局不变量

1. Library 无 Avalonia 引用；接口不暴露 SQLiteConnection 之外的新 UI/供应商类型。已有 IDatabaseService 保留 SQLite 委托。
2. 每个异步读写携带必要的 BookUid、DocumentKey、DataEpoch，VM 另核对 ParameterVersion。数据库整数 Id 不是唯一上下文身份。
3. 所有范围是版本化规范化正文的半开区间；没有“动态页码持久化为正文位置”的兼容捷径。
4. 操作权先于数据库门禁取得；数据库委托内不调用其他异步存储，防止信号量重入。
5. 取消发生在提交前则不写；事务开始后完成提交或回滚，再返回真实结果。不能在已提交后仅因取消 token 被置位而谎报未提交。
6. 关键写入幂等靠数据库唯一约束和业务 ID；UI 禁用按钮仅改善交互。
7. 单例接口不得把“当前书籍”藏在一个未校验的全局字段中；有状态缓存必须按完整身份分区并释放。

## 2. 核心类型

以下 DTO 属于 `ReadJournal.Library.Models.Reader`，可拆分文件。日期持久化不直接依赖 sqlite-net 对 DateTimeOffset 的映射。

所有摘要统一为小写 SHA-256 十六进制字符串，验证长度和合法字符。DocumentKey 中的 FileId 标识不可变源版本；BookUid 标识业务书籍，恢复保留，旧 JSON 输入时新生成。

Range 的开始/结束必须属于同一文档；跨章先比较 spine/章节序号，再比较偏移。空选区不允许保存书摘。图片块可以共享文本偏移，NonTextBlockKey 用于区别定位亲和，不参与小说字数统计。

规范化正文中的图片占位为 U+FFFC，页面抽取转换为多个可引用文本片段；AI 原句不得跨越没有连续原文映射的拼接边界。复制时按定义去除占位，选区保存同时保留原始范围和纯文本映射。

IBookParser 有 TXT/EPUB 两个单例实现，通过 IEnumerable<IBookParser> 按格式选取；解析器不缓存当前书、不写业务表、不移动外部源文件。workspacePath 只能是导入服务生成的受管 staging，源路径只能是已校验的 staged 文件。

规范化目录建议：`document-v1.json` 为 manifest；`chapters/<安全键>.utf16` 保存 UTF-16LE 无 BOM 的规范化正文；独立块/样式索引；resources 保存受限图片。文件位置可按 UTF-16 偏移进行受控随机读取，不必把全书载入内存。键先映射到安全文件名，不把 EPUB href 原样拼成本地路径。

CanonicalSha256 由版本固定的 manifest 核心字段及按序章节/资源摘要派生，不包含自身摘要或导入时间。资源实际存储清单纳入导入日志和备份清单。

ReadSliceAsync 返回边界调整后的实际 StartOffset，不能切断字符簇；布局引擎据此避免重读/漏读。ExtractAsync 保持规范化原文及映射，不做供模型阅读的随意改写。

Blocks 返回与 slice 相交的块，块/样式偏移仍为章节全局 UTF-16 坐标，渲染时与 slice 范围取交集。Image 块在正文中占一个 U+FFFC 单元，几何尺寸来自受检资源信息；OpenResource 仅接受 manifest 已声明的本地键，返回只读流，由调用者释放，禁止通过该接口访问网络或任意绝对路径。UI 解码后仍检查像素预算，并随文档释放图片缓存。目录目标以同一 DocumentKey 的正文锚点表达，嵌套目录不改变 Chapters 的 spine 顺序。

导入/扫描/删除取得正常操作租约；ReconcileAsync 在启动进入主业务前取得独占维护权。存在未解决恢复日志时禁止读取可能混合的新旧书库。

Begin 在首屏成功呈现后调用；保存 HasStarted/LastOpenedAt，分配 SessionId，注册 Reader；不写已关闭会话。若开始事务失败则不进入 Active，界面提供重试。ReaderRegistration 与 session 绑定，在成功离开/取消打开时释放；它用于维护检查，不在整个阅读期间持有数据库门禁或正常操作锁。

EnterOperation 允许并发正常操作，但实际 SQL 仍串行。EnterMaintenance 阻止新正常操作并等待正在执行的短操作结束；如存在活动 ReaderRegistration，返回明确“先退出阅读器”错误，不能等待持有注册的阅读器无限期结束。导航已关闭阅读器后，设置页才能恢复。

注册 Reader 与维护开始必须在协调器内部同步检查；不能出现维护已开始却注册成功。AI 等网络期间不持租约，提交时重新 EnterOperation(expectedEpoch)；不相等则拒绝。维护完成替换后才 CompleteReplacement 更新代际。Backup 不改变代际；Migration/Restore/Reset 在需要失效上下文时更新。

Close 使用 SessionId 主键；同一 SessionId 已提交时返回原结果，绝不重新更新 EbookProgress。不同 payload 的重复关闭先核对已存结果，记录诊断并使用已提交事实，不以新 payload 覆盖历史。新会话从服务实际打开时分配，不能复用已提交 SessionId。

StartPosition/OpenedAt 必须与 Begin 保存的会话起点相同，不能由调用方任意改写；EndPosition 必须属于同一不可变文档。重试先通过 expectedEpoch/BookUid 校验再查提交事实，恢复后的旧上下文不因存在同名 SessionId 而被接受。

EnterActiveAction 在会话内短门禁下核对身份和 Active 状态，返回的租约用于书摘写入、完成标记及 AI 返回后的本地提交；它不跨网络等待。Close 在同一门禁下转 Closing，排空已进入动作后拒绝新动作；随后保存会话。锁顺序固定为“会话动作门禁 → 数据操作租约 → 数据库门禁”，维护操作不反向获取会话门禁。文档只读布局不持动作租约，可随时取消。

CloseFailed 选择继续阅读前，先 FindCommitted。若已提交则收尾旧会话、以当前时间和位置新建会话；未提交则保留同一未提交会话继续计时。这可处理数据库已提交但 UI 丢失确认的情况。

ResetProgress 需要 UI 明确确认，服务检查无活动 ReaderRegistration、计划一致性和身份后事务重置；更新 DataEpoch 需独占维护，以使旧定位任务失效。不得先持普通租约再升级维护锁。

HistoryKey 手动记录使用十进制 Id 字符串，电子书使用 SessionId 的标准 GUID 字符串；解析失败拒绝。统一历史排序按活动时刻倒序，再按 SourceKind/SourceId 稳定排序。旧 ReadingDate 作为原本地日期解释，数据缺少历史时区时不伪造精确历史 UTC。

原 SaveAsync/ToggleFavoriteAsync/DeleteAsync 同步维护 QuoteOrigin、Quote.Revision 和关联状态。SaveLocated/SaveAiBatch 的存储方法负责取得会话动作租约，再取得正常操作租约并核对 epoch、BookUid、DocumentKey 和合法范围；不能只因类型叫 Verified 就信任任意外部输入。正文核验在取得正常操作租约后、事务前进行；文档不可变且租约阻止恢复，可避免事务内文件 IO。上层不重复取得同一个会话动作租约，避免非重入门禁自锁。撤销不要求 Reader 活动，但要求调用者捕获的 expectedEpoch 匹配当前数据集。

IReaderQuoteService 从文档 Extract 得到原句，调用 SaveLocated；VM 不提交“自己拼出的正文”。IReaderAiService 先验证输入范围/限额，网络返回后进行本地原文核验，再调用存储的受保护提交。客户端负责 HTTP/结构解析；编排服务负责身份和业务；QuoteStorage 负责最终租约、唯一约束与原子入库。AnalyzeAsync 只接受 Analyze/ExplainSelection，ExtractQuotes 必须走生成与保存方法。

AI 存储不在整个网络期间持有 Reader 的忙态。并发限制为每 ReaderContext 一次，退出取消 token 并失效 ReaderInstanceId；已自动保存的批次不会因面板关闭自动撤销。

同 BatchId 重试返回原提交结果；新显式生成用新 BatchId，但重复书摘唯一键仍避免重复。拒绝项数由编排传回，不把无效候选插入数据库充数。

Accepted 为 0 时不写 Quote 或批次表，返回零新增及拒绝计数；界面不显示撤销按钮。存在合法但全重复候选时允许保存零新增批次摘要，以支持幂等结果查询；撤销仅把批次标记已撤销，不影响已有书摘。

ISecretStore 是敏感接口，只由设置流程与 HTTP 实现使用。实现不得打印返回值、在错误对象内回显 Key 或将它写入普通偏好。日志只记录操作类型、长度、状态码和不含正文的请求标识。

## 7. 备份、日志与错误类型

```csharp
public sealed record BackupValidationResult(
    bool IsValid, int FormatVersion,
    int BookCount, int ManagedFileCount,
    IReadOnlyList<string> Errors, IReadOnlyList<string> Warnings);

public sealed record BackupExportResult(
    string Path, string Sha256, int ManagedFileCount);

public sealed record RestoreResult(
    string AutomaticBackupPath, DataEpoch NewEpoch,
    int BookCount, int ManagedFileCount);

public interface ICompleteBackupService
{
    Task<BackupValidationResult> ValidateAsync(string path, CancellationToken ct);
    Task<BackupExportResult> ExportAsync(string path, CancellationToken ct);
    Task<RestoreResult> RestoreAsync(string path, CancellationToken ct);
}

public interface IOperationRecoveryService
{
    Task RecoverBeforeBusinessReadyAsync(CancellationToken ct);
}
```

IBackupService 保留原签名作兼容外观：Export/Restore 调用 ICompleteBackupService，Restore 返回自动备份路径；LoadDemo 仍只允许空业务库，包含新增表计数检查。新设置页可直接消费更丰富结果，但不维护第二套恢复实现。

初始化先建立数据协调器和同目录单实例锁；检查未完成日志后，以恢复所需最小方式打开现有共享数据库连接，读取 LastRestoreId 并恢复成套文件；再完成待执行 schema 迁移与正常连接初始化，最后进入主业务。schema 2 的常规恢复无需重复迁移。IDatabaseService.IsInitialized 仅表示连接/结构就绪，不代表 App 已 BusinessReady。底层启动辅助器负责这一顺序，不能从 InitializeAsync 内递归调用会再次初始化同一连接的服务；初始化页面等待整个启动任务，并在恢复失败时停留。

操作日志最少包含 Version、OperationId、Kind、Stage、Source/Target 相对路径、文件摘要、相关 FileId/BookUid、RestoreId、数据库预期状态。日志临时写入后同卷原子替换，记录关键阶段后再推进不可逆动作，资源恢复前检查相对路径范围。

AppMetadata 表含 LastRestoreId 用于决定恢复提交点，初始为空。Import 的已提交事实可由 EbookFile.FileId/SourceSha256 判断；清理日志可根据受管文件引用判断。恢复日志保留至数据库与文件最终校验完成。

错误以业务类型或 Result 中的明确 code 表达，至少区分 InvalidFormat、EncodingRequired、LimitExceeded、Duplicate、FileMissing、DocumentMismatch、StaleContext、OperationCancelled、StorageFailure、RecoveryRequired、CredentialMissing、ProviderUnauthorized、RateLimited、ProviderUnavailable、InvalidAiResponse。UI 显示可操作中文提示，内部日志不包含敏感正文；不把所有错误压成“网络错误”。

文件选择器：导入允许 .txt/.epub，多选；备份保存为 .zip；恢复允许 .zip/.json。验证实际内容，不能仅信扩展名。

### 8.1 导航新增签名与调用约定

向原 IContentNavigationService 与 IMenuNavigationService 分别增加相同异步方法，保留原 void 方法，不替换三层服务和常量：

```csharp
Task<bool> NavigateToAsync(
    string view, object? parameter = null, CancellationToken ct = default);
```

MainViewModel 把现有私有异步门禁改为可供 UI 导航服务调用的入口：

```csharp
public Task<bool> RequestNavigationAsync(
    Action navigationCommit, CancellationToken ct = default);
```

NavigateToAsync 先验证目标/参数，再调用 Main.RequestNavigationAsync；后者串行调用当前页 CanLeaveAsync，允许后在受控提交区间内执行原 NavigateTo 的 SetParameter/PushContent/SetMenuAndContent。取消或离开失败返回 false。VM 的命令等待完成并处理错误，不使用 async void 或丢弃的 Task。

原 NavigateTo 仅供该提交区间或无 Content 的初始化调用；运行期未经门禁直接调用则明确拒绝，不默默切换。现有所有导航 RelayCommand 调用点在 P5 迁为可等待命令，并更新真实导航测试。GoBack 的同步栈变更只在已获准离开后执行；旧页面的保存后返回也先检查当前页面身份，再走统一入口，避免旧完成事件弹走 Reader。

窗口关闭仍保留原 Closing 取消/重入保护，等待 Main.CanCloseAsync；它与 RequestNavigationAsync 共用互斥标记及 Reader.CanLeaveAsync。内容服务不构造注入 MainViewModel，继续按现有 ServiceLocator.Current 获取，避免改变参考架构和引入容器循环。根导航仅用于启动；运行期若新增退出主界面的根路由，也必须先通过该离开门禁。

## 9. SQLite 结构约束与迁移明细

| 表 | 关键列及 SQLite 类型 | 键/约束 |
|---|---|---|
| Book（扩展） | Kind INTEGER NOT NULL DEFAULT 0；BookUid TEXT NOT NULL（迁移填充） | BookUid UNIQUE；Kind∈{0,1}；业务层校验 TotalPages 与 Kind |
| Quote（扩展） | Revision INTEGER NOT NULL DEFAULT 0 | 任意内容/收藏变更递增；原 ID/FK 维持 |
| EbookFile | BookId INTEGER；FileId TEXT；Format INTEGER；SourceRelativePath/CanonicalRelativePath TEXT；SourceSha256/CanonicalSha256 TEXT；SourceBytes INTEGER；ParserVersion INTEGER；ImportedUtcTicks INTEGER；Status INTEGER | BookId PK/FK Book CASCADE；FileId UNIQUE；SourceSha256 UNIQUE；Format 合法；长度非负 |
| EbookProgress | BookId INTEGER；DocumentKeyJson/LastPositionJson TEXT；HasStarted INTEGER；CompletedUtcTicks INTEGER NULL；CompletedOffsetMinutes INTEGER NULL；LastOpenedUtcTicks/LastSavedUtcTicks INTEGER | BookId PK/FK Book CASCADE；位置 JSON 有版本及完整性验证 |
| EbookReadingSession | SessionId TEXT；BookId INTEGER；BookUid TEXT；DocumentKeyJson/StartPositionJson/EndPositionJson TEXT；StartPercent/EndPercent REAL；OpenedUtcTicks/ClosedUtcTicks INTEGER；OpenedOffsetMinutes/ClosedOffsetMinutes INTEGER；DurationMilliseconds INTEGER；CloseLocalDate TEXT；ClockAnomaly INTEGER | SessionId PK；BookId FK CASCADE；Duration≥0；百分比 0～100；BookId+ClosedUtcTicks 索引 |
| QuoteOrigin | QuoteId INTEGER；Source INTEGER；OriginalText TEXT；DocumentKeyJson/StartPositionJson/EndPositionJson TEXT NULL；PrefixHash/SuffixHash TEXT NULL；LocationStatus INTEGER；BatchId TEXT NULL；DedupeKey TEXT NULL | QuoteId PK/FK Quote CASCADE；有定位时 DedupeKey UNIQUE；Manual 无定位允许 NULL；BatchId 是可选来源引用 |
| AiGenerationBatch | BatchId TEXT；BookId INTEGER；BookUid TEXT；DocumentKeyJson TEXT；ScopeSha256 TEXT；CreatedUtcTicks INTEGER；Status INTEGER；InsertedCount/DuplicateCount/RejectedCount INTEGER | BatchId PK；BookId FK Book CASCADE；计数非负 |
| AiGenerationBatchItem | BatchId TEXT；QuoteId INTEGER；CreatedRevision INTEGER；CreatedContentHash TEXT | (BatchId,QuoteId) PK；两端 FK CASCADE；撤销使用创建版本判断 |
| AppMetadata | Key TEXT；Value TEXT | Key PK；LastRestoreId 等非敏感元数据 |

QuoteOrigin.BatchId 若用 FK，应采用 ON DELETE SET NULL；批次先写、来源后写，撤销保留批次摘要但删除实际新增项。关联项删除后仍通过批次计数和状态保证重试返回原结果；批次已撤销时返回 WasAlreadyUndone=true。

BookUid 迁移不能简单给所有旧行同一默认空串。先增加可填充列、逐行生成、验证唯一，再建立唯一索引；若需 NOT NULL 结构重建，必须在单事务内按 FK 依赖复制并核对。Kind/TotalPages 的复杂约束由统一校验与备份校验保障，必要时迁移加入触发器，不假称 ALTER COLUMN 能直接修改旧表所有约束。

位置 JSON 不是任意对象序列化：固定 ContractVersion=1 与字段名，读时校验 DocumentKey/章节/偏移边界。查询不依赖解析 JSON 中的动态页码；主关联、排序、状态均有独立标量列。

Canonical manifest、数据 DTO 和数据库行各有验证器；Import/Backup 共用同一套实体语义校验，防止运行时能保存但备份永远恢复不了。

## 11. 并发与提交点验收摘要

| 场景 | 必须发生的结果 |
|---|---|
| 同一个关闭事件重复 | 单 SessionId 单事务；一次会话，位置不被旧请求重写 |
| 保存成功但 UI 未收到确认 | FindCommitted 找到提交事实，重试不新增 |
| Reader A 的 AI 返回时已切到 B | ReaderInstance/BookUid/DocumentKey 不匹配，零写入 |
| 恢复后出现原有整数 Id 或 BookUid | DataEpoch 失效旧请求，零写入 |
| 两个导入同时处理同一文件 | SourceSha256 UNIQUE，保留一个 Book/File，另一结果 Duplicate |
| 未知 LayoutId 的选区/页号 | 明确失效，拒绝猜测原文 |
| 数据库失败而受管文件已安装 | 日志回退/隔离未引用文件，下次启动不显示半成品 |
| ZIP 恢复在任意阶段崩溃 | 按 LastRestoreId 和日志恢复到完整旧集或完整新集 |
| AI 批次撤销遇到用户修改 | 修改项保留，明确计数，不删除先前已存在的重复书摘 |

所有上述行为都在配套验收执行表分配用例。只有实际编译、集成和目标平台执行通过后才标记完成。
