# 阅记 · 阅读与书摘管理

个人离线阅读记录、书摘、阅读计划与统计应用，使用 .NET 8、Avalonia 和 SQLite。

## 构建和启动

安装 .NET 8 SDK（global.json 固定 8.0.424，允许同补丁带的新补丁），在本目录执行：

```sh
dotnet restore ReadJournal.sln --locked-mode
dotnet build ReadJournal.sln -c Release --no-restore
dotnet test ReadJournal.sln -c Release --no-build --no-restore
dotnet run --project ReadJournal/ReadJournal.csproj -c Release --no-build
```

Windows 可执行 `powershell -ExecutionPolicy Bypass -File build.ps1`，Linux 可执行 `sh build.sh`。首次还原需要 NuGet 网络来源或完整包缓存；业务运行无需联网。Linux 启动需具备桌面图形环境及 Avalonia 所需系统库。

## 使用和数据

手动书籍从“我的书库”新增，在详情中添加页码记录、书摘与计划。第10～20页按闭区间计11页，重复阅读计入累计页数，手动书进度取最大结束页。电子书通过TXT/EPUB导入，详情“开始 / 继续阅读”进入原生阅读器；正文位置与显式完成标记分别保存，不使用物理页数。

默认数据保存在用户 LocalApplicationData 下的 ReadJournal 目录，不写源码目录。设置 `READJOURNAL_DATA_DIR` 可指定隔离目录；设置 `READJOURNAL_LOG_BINDINGS=1` 可输出框架诊断。设置页支持虚构演示数据、浅深主题及完整 ZIP 备份；兼容旧 JSON 输入，恢复前先生成完整自动备份，本机主题和密钥独立保留。

本版修复编辑加载/保存期间的输入保护、编辑页重试、重复计划及状态变化导致备份不可恢复的问题。若旧备份中某本书存在多个完成计划，修改记录或总页数会使多个计划同时未完成时，应用拒绝整次操作并提示先删除多余计划，原数据保持不变。

最新复核补充了删除与导航的异步保护：删除前固定目标书籍并检查页面上下文，已失效的操作不再提交删除；已提交的旧删除完成后不会弹走新的页面或草稿。单例页面在旧操作尚未结束时重新打开，会等待旧操作结束后加载最新参数，避免详情留空。

设置页的数据操作进行期间会阻止切页和关闭窗口，完成或失败后恢复正常导航。概览最近阅读活动由IReadingHistoryService合并手动记录与自动会话提供，ViewModel不直接编写数据库查询。

2026-10-21修复收藏与恢复之间的竞态：收藏由存储服务在单次事务内更新收藏位和时间，不再保存整条旧书摘；所有页面忙碌时禁止菜单、返回、关闭和直接内容跳转，操作完成或失败后可正常离开。请等待当前操作完成后再进入设置恢复备份。

左上角返回仅在当前模块有上一页时显示。详情与编辑页逐级返回，模块首页不显示无效入口；左侧菜单切换会清空当前返回栈，不提供跨菜单浏览历史。返回仍执行忙碌与未保存修改检查。

## 当前 AI 本地流程（P8）

2026-10-23：在已合并的P0～P7基础上完成AI本地流程。阅读器右侧选择当前页、当前选区或当前排版的全书页范围，支持分析、解释及“生成并自动保存书摘”。提交前确认范围、字符数、模型和限额；重排会清空未提交页号，已提交快照保持不变。等待索引和AI时可取消，翻页、返回和正常退出继续可用。

默认使用本地模拟（Mock）：HTTP序列化、结构化响应解析、逐字原句核验与批次入库均在本地执行，不请求DeepSeek、不需要密钥。模拟结果明确标识，不能作为真实模型质量或P9联调结果。分析与解释只显示结果；原句必须在所选连续正文中唯一定位，不能改写、越界或跨图片拼接。合法候选自动保存，重复与拒绝数量及原因显示在面板，书摘页标注AI来源；原句核验不代表解读正确。

保存失败时使用“重试本地保存”，不会再次调用API；同批次回执幂等且不会因删除书摘而丢失。阅读器可撤销刚生成的新增书摘，书摘列表也可按批次撤销；只删除本批未编辑、未收藏的新增项，保留用户改动及此前已有重复项。

设置页可切换Mock、配置官方HTTPS地址/模型/限额/超时，隐藏输入或删除会话密钥。当前跨平台凭据采用**仅会话内存**方式，退出后需重新输入；无明文密钥文件，不包含在普通配置或备份中。真实模式须显式确认上传、配置密钥并主动点击操作，不能自动重试超时请求。P9尚未执行，本阶段没有真实API调用；官方供应商当前能力、计费及密钥平台保护持久化适配需后续按阶段核验，不能据本地Mock宣称真实联调通过。

P8按Linux验收，具体测试数字、故障记录与证据见仓库根目录 `docs/evidence/reader/P8/acceptance.md`，范围与批次边界见 `docs/reader-p8-protocol.md`。P8新增功能的Windows实机验证保留；P7的Windows结果属于历史。P9/P10与正式报告/交付ZIP尚未更新。
