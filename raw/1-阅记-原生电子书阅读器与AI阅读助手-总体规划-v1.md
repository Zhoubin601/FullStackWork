# 「阅记」原生电子书阅读器与 AI 阅读助手扩展规划（v1）

> 性质：需求与技术方案草案，仅用于讨论和后续分阶段实施。**尚未修改 FullStackWork 仓库代码，也没有进行原生分页可行性验证。**  
> 基线仓库：`Zhoubin601/FullStackWork`，工作代码位于 `Code/`，参考源码以规划开始时的 `main` 分支为准。  
> 目标：保持原有阅读管理功能和 Avalonia / .NET 架构，将「阅记」发展为 **本地 TXT/EPUB 小说阅读 + 自动阅读记录 + DeepSeek AI 阅读辅助 + 智能书摘** 的桌面应用。

## 1. 已确定的产品决策

| 主题 | 已确定的方向 |
|---|---|
| 阅读格式 | **TXT + EPUB**；暂不支持 PDF，也不做扫描 PDF/OCR |
| 阅读器实现 | 优先尝试 **Avalonia 原生控件与 C# 文本排版**，不把 WebView/nn-reader 作为主方案 |
| 运行技术栈 | 保留 **.NET 8、Avalonia 11、CommunityToolkit.Mvvm、sqlite-net-pcl、现有 DI 与导航机制**；只在必要时进行小版本升级 |
| EPUB 解析 | 可引入 **VersOne.EpubReader** 解析内容；复杂 EPUB 排版不作为首版目标 |
| 导入文件 | 用户选择 TXT/EPUB；复制到「阅记」受管书库，原文件不受影响 |
| 自动入库 | 启动或手动刷新时扫描指定书库收件区中的新文件；识别和去重后导入 |
| 书库存储 | 固定默认目录（复用现有 `DataPaths`）；未来可以让用户更换根目录 |
| 阅读界面 | 主界面内打开阅读页；支持全屏；**分页阅读为首要模式**，连续滚动后续添加 |
| 阅读进度 | 最后退出时的**稳定正文位置** + 百分比，重新打开恢复；不以历史最高页作为续读位置 |
| 阅读时间 | 用户定义：**结束时间 − 打开时间**，不扣除闲置时间，不做阅读活跃度判定，也无需实时计时器 |
| 自动阅读记录 | 正常退出阅读器时生成一条阅读会话记录，自动出现在现有阅读记录列表中；手动记录保留 |
| 书摘 | 用户选择文字后可保存；AI 可针对当前页、指定若干页、选中段落进行分析/提取原文书摘 |
| AI 供应商 | **DeepSeek API**；本地阅读不联网，仅 AI 调用联网 |
| AI 保存行为 | 「生成 AI 书摘」后对通过原文核验的候选**自动入库**，在书摘页展示并允许编辑、删除、撤销 |
| AI 分析行为 | 分析结果在阅读界面显示，不默认保存为书摘；尽量避免超出指定阅读范围剧透 |

## 2. 当前源码基线与约束

目前代码结构：

```text
Code/
├── ReadJournal/                    # Avalonia 桌面视图与实际导航服务
│   ├── App.axaml(.cs)
│   ├── ServiceLocator.cs
│   ├── ViewLocator.cs
│   ├── Services/{Root,Menu,Content}NavigationService.cs
│   └── Views/*.axaml
├── ReadJournal.Library/            # 模型、ViewModel、存储和业务服务
│   ├── Models/{Book,ReadingRecord,Quote,ReadingPlan,...}.cs
│   ├── ViewModels/*.cs
│   └── Services/{DatabaseService,BookStorage,ReadingRecordStorage,...}.cs
└── ReadJournal.UnitTest/
```

**不得为了阅读器移植而替换的现有基础：**

- 真实 `ServiceCollection` / `BuildServiceProvider()` / `IServiceProvider` / `ServiceLocator.Current`。
- 根导航、菜单导航、内容导航三层体系、导航常量、`SetParameter()` 与 `ViewLocator`。
- 原有书籍、阅读记录、阅读计划、书摘、统计、备份、浅深色主题等业务。
- `DatabaseService` 的串行化访问和事务边界；不另起 FreeSql 数据库体系。

**已发现的数据模型矛盾（必须先处理）：**

1. `Book.TotalPages` 是正整数，`ReadingService.ValidateBook` 要求 `>0`。TXT/EPUB 不存在恒定物理页数；不能将动态排版页数强行当作原有真实页数。
2. `ReadingRecord` 使用 `StartPage`、`EndPage`、`Minutes`；原有 `ReadingService.Calculate()` 用最大 `EndPage` 推断进度。这与电子书最后停留位置、向前跳页及重排冲突。
3. `BookProgress` 和 `ReadingStatistics` 假定以页数表示阅读进度，阅读计划的完成判断也依赖页数计算。
4. `Quote.Page` 是可空整数；TXT/EPUB 的书摘必须另存可稳定定位的章节与偏移信息。
5. `BackupDocument.FormatVersion == 1` 且仅备份业务实体；未覆盖受管书籍文件和新增阅读数据。
6. `DatabaseService` 使用 `PRAGMA user_version=1`；需设计版本迁移，不可清空旧数据库。

## 3. 总体架构（纯 Avalonia 原生方案）

```text
                           ReadJournal / Avalonia 11
                ┌──────────────────┴──────────────────┐
           原有书库与书摘页                    ReaderView（原生控件）
                │                                    │
          原有 ViewModels                     ReaderViewModel
                │                                    │
                │                     ┌──────────────┼──────────────┐
                │                     │              │              │
                │                章节/位置管理     分页渲染       文字选择
                │                     │              │              │
                │                TXT/EPUB 解析   TextLayout      AI 请求
                │                     │              │              │
                └─────────────────────┴──────────────┴──────────────┘
                                      │
                             Service 接口 / DI
                                      │
                       ┌──────────────┼─────────────┐
                       │              │             │
                  EbookStorage    ReadingSession   DeepSeekService
                       │              │             │
                 受管文件目录        SQLite       HTTPS API
                                      │
                                  QuoteStorage
```

分层原则：

- `ReadJournal.Library` 中放无 Avalonia 依赖的电子书模型、解析/存储接口和业务逻辑。
- `ReadJournal` 中放 `ReaderView`、原生文本布局/绘制、UI 输入与文本选择实现；不要让数据服务依赖 `TextLayout`。
- AI 服务只生成与核验结果，**不直接执行 SQL**；书摘写入复用存储接口。
- `ServiceLocator` 注册新增服务/VM，`ContentNavigationConstant`、`ContentNavigationService` 增加 `ReaderView` 路由，保留返回栈机制。
- `ViewLocator` 的 View 缓存、ViewModel 单例和重复进入阅读器必须专门测试：换书时旧内容清理、异步结果隔离、退出持久化只调用一次。

## 4. 建议的数据模型

> 概念结构，不是已确定的数据库列名。正式迁移前先编写数据契约和回归测试。

### 4.1 统一书籍与电子书文件

- `Book` 仍是书籍与书摘/阅读计划的公共主体，保留原有 `Id`、`Title`、`Author` 等；增加区分手动书籍/电子书的 `Kind`（旧数据默认 `Manual`）。
- 对电子书不要求填写纸质书的 `TotalPages`：建议 `TotalPages=0` 仅在 `Kind=Ebook` 下允许；原有手动书籍继续要求正数。所有使用 `BookProgress` 的代码须根据种类分别计算和展示。**这属于必要的兼容性改造，不能只改 UI。**
- 新增 `EbookFile`：`BookId`、`Format`(TXT/EPUB)、`RelativePath`、文件散列、大小、标题/作者来源、导入时间、解析状态。
- 新增 `EbookProgress`：`BookId`、稳定阅读位置、`ProgressPercent`、最后打开时间/保存时间。百分比可以回退，**最后位置不等于历史最大阅读位置**。

### 4.2 阅读记录与统计兼容

- 保留原 `ReadingRecord`：继续对应纸质书/原有手动页码记录，避免虚构 TXT/EPUB 的真实页数。
- 新增 `EbookReadingSession`：`Id`、`BookId`、`OpenedAt`、`ClosedAt`、`DurationMinutes`、起始位置、结束位置、起止百分比、来源标识。
- 用读模型（如 `ReadingHistoryItem`）把手动记录与电子书会话**合并展示在书籍详情和最近阅读列表**，不要求把数字文本位置硬塞进 `StartPage/EndPage`。
- 统计：阅读分钟数汇总两类来源；实体页数仅统计真实页码来源；电子书展示阅读百分比、会话次数和时长。避免把百分比差直接当成页数。
- 完成状态与阅读计划：纸质书沿用原逻辑；电子书使用稳定阅读位置/完成百分比独立判断，再统一提供给计划和概览页面。
- 同一退出事件只能创建**一条**会话；跨天会话第一版可按退出日期归档，后续再考虑跨天拆分。
- 当前 `ReadingRecord.Minutes > 0`，电子书会话不足一分钟可暂按向上取整为 1 分钟入库；需在 UI 说明，避免让用户误以为精确计时。

### 4.3 书摘定位

- 原 `Quote` 的 `BookId`、`Text`、`Thoughts`、收藏和时间字段全部保留。
- 新增书摘来源 `Manual` / `AiGenerated`（可通过扩展字段或关联表），并保存 `ChapterKey`、`TextStartOffset`、`TextEndOffset`、片段校验摘要/上下文以便回跳与核验。
- `Quote.Page` 对电子书留空；阅读器上展示的动态页码只是即时界面信息，不应成为唯一的持久定位依据。

## 5. 固定书库、导入与扫描

沿用 `DataPaths` 默认根目录：Windows 通常是 `%LOCALAPPDATA%/ReadJournal`，其他系统使用其各自的 LocalApplicationData 路径。

```text
ReadJournal/
├── readjournal.sqlite3
├── books/
│   ├── managed/
│   │   ├── <guid-1>/source.txt
│   │   └── <guid-2>/source.epub
│   ├── 用户直接放入的小说A.txt   # 自动扫描收件区
│   └── 用户直接放入的小说B.epub
├── covers/
└── backups/
```

导入流程：校验扩展名/文件签名与大小 → 复制到临时位置 → 计算散列去重 → 解析元数据与可读性 → 写入受管目录 + 数据库事务 → 通知书架刷新；失败时清理临时资源，不留“数据库有记录、文件不存在”的半成品。对于外部文件选择导入**只复制、不删除原件**。

自动扫描只检查 `books/` 根目录（不递归扫描 `managed/`）。对成功导入的收件文件可在告知该目录用途的前提下归档/移动到 `managed/`，防止重复扫描；导入失败的文件保留并给出原因。推荐有“刷新书库”和“打开书库目录”两个入口。

同名不同内容允许分别导入；相同散列可提示或自动跳过。后续再增加书库根目录修改与安全迁移，不在首版实现。

## 6. 原生阅读器设计

### 6.1 第一版界面

- 从书籍详情点击“开始/继续阅读”，通过内容导航进入 `ReaderView`；返回后刷新书籍详情、记录和概览。
- 中间正文分页阅读；左侧可打开章节目录；底部显示**当前布局页码（仅 UI）**、进度百分比和上一页/下一页；右侧或弹层可调用 AI。
- 支持键盘左右方向键、鼠标按钮翻页；快捷全屏/退出全屏；第一版先做一个阅读区域，不强求双栏/多窗口。
- TXT/EPUB 可设置字号、字体、行距、页边距和浅深/护眼背景；改动后重排但要回到相同的正文锚点。
- 选中文字可执行“复制”“添加书摘”“AI 解释”；来源正文与书摘保存关联稳定位置。

### 6.2 文档解析

- `TxtBookParser`：字符编码处理（优先 BOM/UTF-8，按需增加中文编码检测）、换行标准化、可选章节标题识别；需防止把全部大型 TXT 渲染进一个单一控件。
- `EpubBookParser`：优先用 `VersOne.EpubReader` 获取元数据、spine/章节、正文 XHTML、图片资源；转成我们自己的中间文档模型。首版覆盖**文字为主的流式 EPUB**；DRM、复杂 CSS/脚本、固定布局、数学公式等不作完整兼容承诺。
- `ReaderDocument`：章节、正文块、简单样式和图片（可作为后续扩展），每个块映射回 EPUB spine 项或 TXT 原文段。
- 记录位置：TXT 使用版本固定的文本偏移；EPUB 使用 spine 项/章节标识 + 章节内偏移，辅以前后文校验。绝不能仅保存随字体变化的布局页序号。

### 6.3 分页引擎（主要技术风险）

- 使用 Avalonia `TextLayout` 测量、换行和排布文本，优先做**纯文本分页**；文字选择可从每页只读 TextBox 起步，之后再评估复杂混排选择。
- 以可用阅读区域尺寸和字体配置生成分页缓存；窗口变化、字号变化时使缓存失效，并按稳定锚点重新定位。
- 按章节/段落渐进加载，避免长篇小说一次性计算全部页面造成卡顿；优先缓存当前页及附近页。
- 文章中英文标点、中文断行、段首缩进、章节边界、空行、极长段落和图片尺寸都需要单独测试。
- 如果 EPUB 样式保真与原生分页矛盾，以“适合读小说、文本准确、性能稳定”为首版标准，而不是模仿完整浏览器排版。

## 7. 阅读时长与进度行为

用户已确定：**打开阅读器开始，正常退出阅读器结束，二者做差就是阅读时长，不排除挂机时间**。

建议会话状态机：

```text
未打开 → Open(记录 BookId、OpenedAt、起始锚点)
       → 阅读 / 翻页 / 修改字号（只改变 UI 与最后锚点）
       → Leave/Close(取 ClosedAt、最终锚点、计算时长)
       → SaveSessionAndProgressAsync(单次事务，幂等)
       → 返回书库
```

- `OpenedAt/ClosedAt` 使用带时区偏移的系统时间，取差得 `TimeSpan`；不必额外 UI 定时器。
- 第一版会话于正常关闭/离开时落库，保证没有重复保存；通过幂等 ID 防止点击返回和窗口关闭双重触发。
- 异常崩溃可能造成此次时长丢失，这是按目前简化需求做出的有意识取舍；未来如需防丢失，可只增加少量检查点而不改变用户“打开到退出即阅读时长”的定义。
- 退出时保存的最后锚点可后退；进度条显示当前百分比，不将其改写为历史最高进度。

## 8. DeepSeek AI 阅读助手

### 8.1 范围

1. **分析当前显示页**：概述内容、解释难点、讨论人物/观点；只读取当前显示正文。
2. **分析指定页面范围**：选择“当前排版的第 X～Y 页”，由分页器提取对应正文；发送前展示页数/文本长度，禁止超范围读取。
3. **解释选中文字**：对选中的句子/段落生成解释。
4. **AI 自动生成书摘**：从指定单页或多页提取若干个**真实原文片段**与解读，程序校验原文位置后**自动保存到书摘页**，提供编辑/删除/撤销及 AI 来源标记。

“AI 分析”与“AI 自动书摘”应是两个不同的操作：前者默认只显示分析面板；后者才写入书摘数据库。

### 8.2 数据与可信性

```text
ReaderView 当前页/范围
  → ReaderDocument 提取准确正文和章节锚点
  → AiReaderService 构造提示词与请求
  → DeepSeek HTTPS API
  → 结构化输出（原文片段 + 解读 + 候选锚点）
  → 在原始正文中逐条定位并核验；无法匹配的不保存为“原文”
  → QuoteStorage 批量保存（避免重复）
  → 书摘页刷新，可回跳原文
```

- 明确要求模型仅根据传入内容回答，不编造人物、原句或页码；防剧透以“仅提供用户已选范围文本”为主，提示词约束为辅。
- 页面是动态的：每次 AI 操作以**当时的分页布局**为准，长期引用写入章节与稳定偏移，不保存仅靠显示页码的引用。
- 处理长文本应设输入长度/费用上限；若请求跨多页过大，分片生成、合并去重，避免截断和成本失控。
- 对 API 错误、速率限制、超时、网络离线提供清楚提示和重试；**AI 失败不影响本地阅读和阅读记录**。
- 用户自行在“设置”填写 API Key，不硬编码进代码、日志或备份；优先使用操作系统安全凭据存储或受系统保护的加密存储。
- 第一次调用前说明：选中的小说正文会上传给 DeepSeek；不在后台偷偷上传整本书。

## 9. 开发顺序与阶段验收

| 阶段 | 实施内容 | 最低验收标准 |
|---|---|---|
| **0. 原生可行性实验** | 单独实验分支，仅对样例 TXT 实现分页、翻页、中文排版、选择文本、字号/窗口重排 | 不依赖 WebView；至少中文/英文、长段落、修改字号和恢复偏移可正确工作；对超长文本无明显卡死 |
| **1. 模型与数据迁移** | EbookFile、EbookProgress、EbookReadingSession、书摘锚点、`Book.Kind`；`user_version=2` 与老数据回归 | 旧书、旧阅读记录/书摘/阅读计划无损；旧 JSON 备份仍有明确兼容路径 |
| **2. 受管书库与 TXT** | 文件导入、复制、去重、扫描；TXT 阅读、阅读进度、正常退出时间差、统一阅读历史 | 导入 TXT → 打开 → 阅读 → 退出 → 在书籍详情看到自动记录 → 重启后恢复位置 |
| **3. EPUB** | VersOne 解析、章节目录、基本文本样式/图片、稳定位置与原生翻页 | 多本常见文字 EPUB 可以阅读、跳章、改字号后续读，导入不破坏原书 |
| **4. 手动书摘与统计融合** | 选中文本存书摘、书摘回跳、总时长合并、数字书进度与完成态/计划适配 | 原手动业务仍正常；电子书书摘可定位；不虚增纸质页数 |
| **5. DeepSeek AI** | API 配置、分析当前/多页、选择文本解释、AI 自动书摘保存和去重 | 原句逐条校验；生成后自动出现在书摘页；失败不写入伪原文；阅读可离线运行 |
| **6. 完善与交付** | 大文本性能、异常文件、数据库备份升级、UI/无障碍、跨平台与回归测试 | 自动化测试及 Windows 实机测试；备份恢复能包含受管书籍和关联数据 |

**开发策略：** 每阶段单独提交和测试；阶段 0 若原生分页/选中文字达不到体验要求，再评估回退到 HTML/WebView，不在未验证前承诺所有 EPUB 都可完美支持。

## 10. 测试重点与风险

| 风险 | 应对措施 |
|---|---|
| 原生 EPUB 排版兼容性 | 限定文字类 EPUB；先做好正文准确性、字体和章节，不承诺复杂 CSS 保真 |
| 大 TXT 和重排卡顿 | 按章/块加载，分页缓存与失效规则，样例压力测试 |
| 导入中断/重复/同名 | 临时文件、校验、文件散列、数据库事务、幂等导入 |
| ViewModel/视图缓存造成串书 | 利用现有 `ParameterVersion`，检测异步结果是否仍属于当前书，退出只提交一次 |
| 老书籍进度与阅读计划被改坏 | 将纸质书和电子书计算规则分开，构造旧库/旧备份的回归测试 |
| AI 引用伪造与剧透 | 原文严格匹配，限制上传范围，明确 AI 标记，无法核验的结果不自动保存 |
| API Key 泄露/费用 | 受保护存储，输入量限制，UI 显示发送长度，日志不记录密钥/全文 |
| 新增文件的备份恢复 | 规划包含原书文件的 ZIP 备份 + manifest/校验，兼容旧 JSON 纯业务备份 |
| 软件异常关闭 | 首版接受本次会话未持久化风险；以后可加检查点，不引入活跃度判断 |
| 开源代码许可证 | 可参考 MoonReaderPC 和 Readest 的设计，但**不直接复制** AGPL 的 nn-reader / Readest 代码；本方案使用原生 Avalonia 和许可证核验后的 EPUB 解析库 |

## 11. 当前暂不做的事情

- PDF、OCR、MOBI/AZW3、DRM 电子书。
- 跨设备云同步、用户账户、在线书城、在线获取盗版内容。
- AI 全书向量检索、联网推荐、对整本小说的自动后台分析。
- 阅读活跃度判定、闲置时间扣除、摄像头监测。
- 首版双栏精排、复杂 EPUB CSS 的完整兼容、运行任意 EPUB 脚本。
- 为新功能更换原有 DI/导航/SQLite 数据技术栈。

## 12. 开始开发前的设计验收点

1. **数据语义**：电子书允许 `TotalPages=0` 且手动书仍保持正整数；完整列出所有依赖页数的旧代码并补回归测试。
2. **分页/定位契约**：`ReaderPosition` 如何稳定识别 TXT/EPUB 原文以及重排后的锚点；分页器要能返回每页正文对应的原文范围。
3. **退出契约**：导航返回、窗口关闭、切换书籍只生成一次阅读会话；与原有 `CanLeaveAsync` 统一。
4. **备份契约**：老 JSON 备份继续可读；电子书完整备份包含受管文件与新表，防止恢复后只剩书名没有正文。
5. **AI 契约**：谁触发上传、上传范围、返回的原文核验、自动保存与可撤销行为全部可测试。

---

### 综合判断

这套方案**可以尝试在现有 .NET 8 + Avalonia 11 项目上实现**。技术上最大的未知不是 DeepSeek API，而是**原生分页/文本选择的体验及普通 EPUB 的排版兼容性**。最合理的第一步是做一个不改动原项目业务的 **TXT 原生分页可行性实验**；实验通过后再展开模型迁移、正式导入及 EPUB/AI 功能。
