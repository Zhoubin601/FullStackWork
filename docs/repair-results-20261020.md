## 修复对应

| 原问题 | 修复及证据 |
|---|---|
| 加载覆盖输入 | Book/Quote/Plan编辑页按字段合并未改值，保留首Loaded前、读取等待期间及失败后重试期间的草稿；选项和计划建议仍正常加载 |
| 未加载资料被保存为空字段 | EditViewModelBase增加首次成功加载门禁，读取失败后拒绝保存，重新加载成功再允许；记录弹窗参数已完整赋值时标记就绪 |
| 保存期间输入丢失 | 仅将实际提交的快照记作已保存；有新输入则继续留页并提示。CanLeaveAsync采用同一规则；四类编辑器保存成功均回填实体主键，再次保存更新同一实体 |
| 多计划状态破坏备份 | 保存计划始终拒绝同书另有计划；旧备份中的多个完成计划仍保留。记录删除/改页/换书、书籍增总页会使多个历史计划同时未完成时，在同一写事务内拒绝整个操作，提示先清理多余计划，不自动丢弃数据 |
| 编辑失败无重试 | 书籍、书摘编辑页补充重新加载；四个编辑页在IsBusy时禁用输入和保存，VM自身仍保留上述保护 |
| 报告身份与正式文件缺失 | 封面补齐用户提供的姓名、学号、班级，更新当前源码数量、68项结果、新界面和修复机制；正式PDF进入output |

保留老师示例的ServiceCollection、BuildServiceProvider、IServiceProvider、单例定位器、三层导航、SetParameter、主VM返回栈和反射缓存ViewLocator。没有改造原架构或升级依赖。

## 复验结果

- 编辑永久回归20项：加载前/中输入、未改字段水合、失败保存门禁与重试；四种编辑器保存及保存离开期间输入留页、新建ID复用。独立审阅代理另执行7项只读复核用例，全部通过，重要场景已纳入永久回归。
- 计划永久回归8项：普通重复关联提前拒绝；历史多个完成计划的删记录、改末页、换书、增总页操作无部分写入，清理后可正常修改；安全修改保留历史；并发唯一性；真实SQLite和JSON往返。
- 真实UI失败注入：对隔离库施加SQLite独占锁，打开书籍编辑触发读取失败；保存被门禁阻止，解除锁后点击重新加载，原资料完整恢复。此为明确的测试故障注入，不是正常录入步骤。
- 真实UI计划：把演示中的已有计划改关联至已有计划的完成书籍，应用明确拒绝，数据库关联仍为原值。随后通过系统文件选择器导出和恢复，四表分别保持3/4/2/3条，自动备份存在，重启后保留。
- 最终包首次及再次启动成功；SQLite版本1。Linux图形环境仍有会话管理器/DBus/软件GLX回退提示，实际操作正常，未将其冒称GPU硬件验证。
- 构建0错误，固定SQLite依赖仍产生3条NETSDK1206旧Alpine RID警告；Linux x64已实测，Alpine和Windows未实测。

此前独立审计的5项失败用例保留为历史证据。其前3项正确行为由编辑回归覆盖；后2项修复后在重复计划关联这一步即应被拒绝，因此永久回归验证“拒绝、无部分写入、备份可恢复”，不继续强行构造现在已禁止的普通操作路径。
