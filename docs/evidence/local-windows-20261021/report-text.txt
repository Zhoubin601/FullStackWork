阅记·阅读与书摘管理
项目报告
项目背景与意义
个人阅读中，书籍资料、阅读活动与摘录通常分散记录。阅记以本地离线应用统一管理这三类
信息，并由阅读记录推导当前进度、计划状态和统计结果，使用户能够追踪阅读活动、整理感想及
恢复自己的数据。
项目不提供电子书阅读器、账号登录、联网检索或云同步。其业务边界是“记录阅读”，用户
录入的阅读记录表示自身活动声明，不能据此推断所有未记录页段均已读过。演示数据中的书名、
作者、摘录和感想均明确标注为虚构资料。

需求分析
1.1
功能需求
应用实现录入书籍、制定计划、记录阅读、整理书摘和查看统计的完整闭环。十个独立业务页
面及主要能力如下。
页面
已实现能力
阅读概览
在读书籍、近期记录、待完成计划、全量累计指标、书库与详情入
口。
我的书库
书名或作者搜索、未开始/在读/已完成筛选、每页10 本分页、新增
及详情入口。
书籍详情
资料、当前进度、累计活动、记录增改删弹窗、关联书摘与计划、级
联删除确认。
书籍编辑
书名、作者、分类、总页数与简介编辑，校验已有最大引用页码。
书摘列表
正文或书名搜索、收藏筛选、编辑、收藏切换和删除。
书摘编辑
选择书籍、编辑摘录与感想、可选页码和收藏状态。
阅读计划
查看进行中、已完成与已逾期计划，编辑和删除。
计划编辑
选择书籍、设定目标日期、根据剩余页数和天数展示建议。
阅读统计
累计页数、分钟数、完成书籍数与近七日阅读趋势。
设置与数据
浅深主题、空库载入虚构演示数据、JSON 导出与带自动备份的恢
复。
初始化页、主窗口、主容器和阅读记录弹窗不用于补足十个业务页面。编辑未保存时，返回、
切换菜单与关闭窗口共用保存、放弃、取消离开语义；保存失败保留草稿。列表返回刷新数据，保
留当前搜索条件。

非功能需求

功能模块设计
菜单提供概览、书库、书摘、计划、统计及设置六个入口。书库进入详情或书籍编辑；详情进

截，避免覆盖栈中原参数；不同书籍经返回书库再打开，不构造同类型详情的多份历史快照。

记录约束为1 ≤起始页≤结束页≤总页数、分钟数为正整数、日期不晚于本地当天。当前
页取最大结束页，无记录为0；累计页数对每条记录求闭区间长度之和，包含重读。完成日期为读
至末页记录的最早日期。修改记录或总页数后由有效数据重新推导状态。
新建或编辑计划时，同一本书不能再关联第二个计划；普通新计划不能关联已完成书籍。旧备
份中的多个完成计划可保留，但修改记录或总页数会使其同时变为未完成时，整个操作拒绝并提示
先清理多余计划。未逾期的建议每日页数为剩余页数除以包含当天的剩余天数后向上取整；完成为
0；逾期单列状态与剩余页数。删除计划不删除记录。

首轮失败

引入参数版本校验，旧请求不发布到新参数页面；加载命令发
现版本变化继续加载新参数。延迟任务用例验证A 不会覆盖B。

主ViewModel 共用防重入保护；返回、菜单、关闭不会并发
打开多个确认窗口。保存失败保留草稿。
绑定诊断
事件命令显式绑定同一资源定位器中的单例，解决构造时Dat-
aContext 未就绪；进度条使用静态模板，避免固定Fluent 版
本动画绑定。最终遍历十页绑定诊断为0。
原生选择器驱动
GTK 路径自动补全曾干扰测试输入，应用正确提示文件不存在。
通过真实列表选择同一文件后恢复成功，未用后台写库代替UI
恢复。
本轮复核还发现加载与保存期间输入保护不足，以及计划状态变化与备份校验不一致。修复
后，表单按字段合并未改值并保留用户修改，保存仅确认实际提交的快照；保存中新增修改保留在
编辑页，新建成功回填主键避免重复插入。加载失败后可在编辑页重新加载。计划变更、记录修改
与总页数修改在同一数据库事务中维护约束，拒绝不安全操作且不删除原数据。
重复目标拦截、参数版本、草稿保护、串行写入和事务均为阅记新增业务正确性措施。参考
README 明确未解决线程与原子性，不能把这些新增设计称为参考项目原有机制。
