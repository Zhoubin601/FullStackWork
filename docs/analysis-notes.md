## 补充的业务解释

1. 原公式 `0 ≤ 起始页 < 结束页` 配合差值并非数学上不成立，可解释为从“已读页数”前进到新进度；但原页面字段叫起始页、结束页，容易被理解为实际页码。因此采用审议提出的闭区间，而非宣称旧公式本身一定错误。
2. 阅读记录改为 `1 ≤ 起始页 ≤ 结束页 ≤ 总页数`，单条阅读页数为 `结束页 - 起始页 + 1`。无记录的当前进度仍可为 0；该值不是可输入的实际页码。
3. 重读、重叠页段允许记录，累计阅读页数包含这些活动，可以超过书籍总页数；当前进度只取最大结束页，最高为 100%。默认新增起始页为当前进度加 1，已读完时可手动选择重读页段。
4. 记录到最后一页表示用户声明读至书末，不证明每一页均有日志。完成日期为当前有效记录中，结束页等于总页数的最早阅读日期；编辑、删除、修改总页数后重新计算。
5. 完成后不能用普通默认操作创建越界记录；新增弹窗进入重读输入状态并要求选择合法页段。

## 用户明确架构约束后的 v4 修订

2026-10-20 用户要求严格按照老师的说法和示例实施，尤其强调 ServiceLocator 必须基于真实 IoC 容器，不能只是保存所有实例的集合。这比指导书“思想对应即可”更严格，是优先适用的用户选择。

v3 提到了 ServiceCollection 和依赖注入，但没有写全 BuildServiceProvider、IServiceProvider、定位器属性解析及应用资源接入约束，还额外引入了导航宿主和页面工厂。针对当前用户目标，收回这些自由度与额外层次。

重新对照参考项目 ServiceLocator.cs、App.axaml、ViewLocator.cs、三类导航服务及接口、MainViewModel.cs、MainWindowViewModel.cs，确定：

- ServiceCollection 用于注册；BuildServiceProvider 构建容器；定位器保存 IServiceProvider，属性调用 GetService<T>，由容器构造实例和注入依赖。
- 定位器在 App.axaml 资源中注册，Current 从应用资源读取。禁止手动 new 全套业务依赖再用字典或属性伪装容器。
- MainViewModel 构造注入菜单接口；导航服务只在 NavigateTo 时经定位器取得 VM，不反向构造注入主 VM，因此不需另加宿主层来处理假设的构造循环。
- 撤销 ShellViewModel、IMainNavigationHost、IPageFactory；保留三层导航、MainViewModel 菜单及返回栈、SetParameter 和三类导航常量，调用方式对应示例。
- 服务和全部 VM 采用 AddSingleton；ViewLocator 反射定位并按类型缓存。撤销瞬时页面及预加载后才提交导航栈的设计。
- 单例详情不承诺同类型页面的多份历史快照；采用列表到详情/编辑再返回，同实例不重复入栈，重新传参清理旧状态。测试与加载失败处理已同步调整。
- 必要业务校验、异步错误处理和明显参考代码错误仍须修正，不以修错为理由改造核心架构。

本轮只修改规划和过程记录。真实容器、导航及单例行为须在应用实现后验证，不能把源码阅读当作新项目测试通过。
