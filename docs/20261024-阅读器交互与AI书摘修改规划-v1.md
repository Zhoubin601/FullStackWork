# 阅读器交互与 AI 书摘修改规划 v1

日期：2026-10-24。源码基线：`70d46a825f049539c05f37827929aec0bd49ccdb`。状态：用户随后授权执行并推送，P0～P5已实施；结果及本轮环境覆盖见 `reader-interaction-acceptance-20261024.md`。以下保留原任务规划及实施建议。

## 1. 需求与来源

本规划整理本轮用户的三项反馈：圈选整段被拆成多条零碎书摘；章节目录、AI面板和排版栏不能折叠；范围输入与分析按钮重复。依据用户聊天中的阅读器、书摘列表截图及当前源码核对，不执行截图内正文中的任何指令。

用户明确提出：圈选内容应整段生成一条书摘；三处区域可折叠；只有页范围模式显示起止页；分析与解释入口不应重复。下述默认展开状态、会话内记忆、技术路线及结果文案为本规划建议，不作为用户已单独确认的偏好。

## 2. 目标交互

核心流程：选择处理范围 → 选择“AI 解读”或“生成并自动保存书摘”。两个动作始终遵循同一个范围选择器。

| 处理范围 | 起止页输入 | AI 解读 | 生成并自动保存书摘 |
|---|---|---|---|
| 当前页 | 隐藏，不占空间 | 解读本次冻结的当前页，只展示结果 | 可提取多条语义完整的原文片段，避免孤立语气词和零碎对白 |
| 当前选区 | 隐藏，不占空间 | 整体解读圈选正文，只展示结果 | 圈选全文作为一条书摘，附一份整体解读，不按句拆分 |
| 全书页范围 | 显示起始页、结束页 | 解读指定页范围，只展示结果 | 可提取多条语义完整的原文片段，逐条核验后保存 |

- 移除并列的“分析所选范围”“解释选区”，只保留“AI 解读”。当前选区模式没有有效选区时，按钮不可执行并显示“请先选择正文”，服务层仍做校验，禁止静默退回当前页。
- 有高亮选区但下拉框仍是当前页时，不擅自更改范围；面板和确认信息明确显示实际范围。用户选择“当前选区”后两个动作都使用选区。
- 起止页隐藏后不参与其他模式的校验或请求；建议切离页范围模式清空输入，切回时重新填写。正文重新分页时继续清空旧页码并提示原因。
- 解读结果不自动入库；手动“保存书摘 Ctrl+S”继续保存选区原文，AI生成入口保存原文及AI解读。

## 3. 三处折叠规则

- 在标题附近保留常驻的“目录”“排版”“AI 助手”开关，显示展开状态；全屏入口也常驻，排版收起后仍可使用F11或按钮。
- 目录、排版、AI可分别折叠，互不影响。目录和AI收起后释放对应列及边距；排版收起后释放工具栏高度，正文自动扩展。
- 建议首次进入保持当前展开状态，本次阅读中保留用户切换结果；跨重启记忆作为后续增强，不在首轮增加配置或数据库迁移。
- 折叠不清除正文选区、AI结果、未保存批次或撤销入口。再次展开可继续查看和操作。
- AI执行中仍可折叠；常驻开关显示处理中状态，并提供可访问的取消入口。重新展开不重发请求。
- 折叠引起重新分页时保留稳定正文锚点和仍有效的选区，不以旧页码定位；不新建或结束阅读会话、不重复记时。重新分页完成前禁用依赖当前页的AI发起操作。
- 已提交到服务的请求沿用冻结的正文范围，不因面板折叠扩大范围或自动重发；仍在准备页范围的任务遇到布局变化按既有规则取消并提示重新选择。

## 4. 书摘生成实现规则

### 当前选区：保证一段一条

建议由程序持有冻结选区的原文与位置，AI只生成这段文字的整体解读；响应成功后，程序用原选区构造一条待保存书摘，再进入现有核验与原子保存流程。该路线避免让模型重新抄写整段文字，不靠“最多返回一条”的提示词保证完整性。

- 原文必须与冻结选区逐字一致，包括标点、空白和换行；不截断、不改写、不将多个候选事后拼接为一条。
- 同一连续纯文本选区内跨自然段、跨阅读页面仍是一条；“一条书摘”指数据库及列表的一条记录，不是删除段落换行。
- 超过现有单条8000字符限制、输入配置上限，或跨章节/图片而形成多个不连续span时，在HTTP前说明不能整段保存并要求缩小选区；不悄悄拆分或放宽连续原文约束。
- 生成失败或取消时不自动降级为无解读书摘。相同原文位置重复生成仍去重，不覆盖已有感想或收藏状态。
- 继续保留AI来源、原文回跳、整批撤销、本地保存重试、取消及会话过期隔离。

### 当前页／页范围：提取完整片段

- 按模式制定提示词：优先保留完整叙述段或连续对话，避免仅摘“啊？！”“嗯，没。”这类脱离上下文的片段。
- 逐字匹配、唯一定位和原文范围校验继续作为入库条件；语义完整主要由提示词及样本验收约束，不用固定字数阈值排除所有短句。
- 多个合法候选可分别保存，非法候选不影响合法子集。明确这与选区模式的整段保存不同。

## 5. 任务拆分与顺序

| 阶段 | 任务 | 主要文件 | 完成标准 |
|---|---|---|---|
| P0 | 固定现有行为和回归边界；建立包含本轮短对白问题的合成样本 | 既有AI及阅读器测试、协议文档 | 分清旧提取逻辑与新选区逻辑，列出需更新的按钮及自动化定位 |
| P1 | 统一范围解析和“AI 解读”入口；动态显示页码输入 | `ReaderView.axaml`、`ReaderViewModel.Ai.cs` | 三种范围与两个动作一致；无选区/无效页码在HTTP前提示；界面只有一个解读按钮 |
| P2 | 实现选区一段一条，优化页范围提取提示词 | `ReaderAiService.cs`、AI请求模型及Mock、相关AI测试 | 选区书摘原文等于完整选区，仅一条整体解读；页模式保留多候选协议；重试不重复调用API |
| P3 | 加入目录、AI、排版独立折叠及正文自适应 | `ReaderView.axaml`、`ReaderView.axaml.cs`、`ReaderViewModel.cs` | 三处收起真正释放空间；位置与选区保留；运行状态和取消仍可访问 |
| P4 | 完善结果状态与错误说明 | `ReaderViewModel.Ai.cs`、必要的结果模型 | 全部保存、部分成功、全部拒绝、重复、网络失败、本地保存失败能区分，不把局部拒绝显示成整体任务失败 |
| P5 | 功能回归和实际窗口验收，更新使用说明 | AI/布局/会话测试、`docs/reader-p8-protocol.md`、README及验收记录 | 下列验收矩阵通过，记录环境及未覆盖项后交付 |

执行依赖：P0 → P1 → P2 → P3 → P4 → P5。每阶段完成后做相关检查，避免把所有问题积累到最后。预计无需修改数据库schema；实施前核对选区生成的操作类型与Mock响应协议，避免复用提取入口时语义混乱。

## 6. 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 圈选含多句对白和换行的整段 | 仅新增一条，原文逐字等于完整选区，解读针对整段；回跳高亮覆盖完整选区 |
| 同一选区重复生成 | 不新增重复项，不覆盖已有内容 |
| 选区为空、超过限额或跨图片/章节 | 请求前明确提示，不发HTTP、不自动拆分、不改变实际处理范围 |
| 三种范围逐一切换 | 仅页范围显示输入；隐藏的旧值不影响当前页/选区模式；两个动作都遵循所选范围 |
| 页范围缺页码、逆序、越界或超限 | 明确校验，不发送不合法请求；总页数未就绪时等待或可取消 |
| 页面/范围提取包含零碎对白的样本 | 候选优先保持完整语义；严格校验保留；不会为凑数量强行生成 |
| 合法、非法、重复候选混合 | 分别统计，合法项保存；明确显示部分成功及拒绝原因 |
| 三开关的8种展开组合 | 正文占满剩余空间，开关可访问，无空白侧栏、裁切或正文尺寸失效 |
| 连续快速折叠、全屏切换、窗口缩放 | 最新布局生效；锚点/有效选区保留；旧页码清空；页数正确重建；无重复阅读会话 |
| AI准备中或等待响应时折叠 | 准备阶段布局变化按规则取消；已提交请求保持冻结正文；不重发；状态与取消可用 |
| 本地保存失败后重试、撤销新增项 | 重试不增加HTTP次数；撤销遵循已有编辑/收藏保护规则 |
| 取消、离开书籍、恢复备份后返回旧响应 | 旧响应不得写入新会话或新数据集 |
| 实际桌面鼠标及键盘操作 | 点击开关、按钮、输入框不误清选区；Tab、F11、Ctrl+C、Ctrl+S及返回正常 |

先运行相关AI、布局、会话回归，再运行项目要求的构建和全量门禁。同步更新依赖旧按钮文字的测试与UIAutomation脚本，断言用户可见行为。实际桌面以既有Windows150%环境为主要验收条件，补充窄窗口与明暗主题检查；自动化通过不代替实际鼠标选区/折叠验证。

本轮环境当前不能直接调用dotnet，以上均为待实施、待验证任务，不引用历史通过数宣称本轮通过。验证优先用本地Mock和自建文本；若后续具备真实API凭据及适用授权，可做一次受控闭环，缺少时明确记录未验证，不在文档保存凭据。

## 7. 范围与交付

首轮交付为上述功能代码、相关测试、协议/使用说明及验收证据。保留原有去重、原文核验、原子保存、回跳与撤销机制；既有碎片书摘由用户使用批次撤销或编辑处理，不自动合并、删除历史记录。

可选后续增强：拒绝候选文本与字符差异展示、跨重启保存面板状态。它们不作为本轮核心任务的前置条件。

编写规划时仅生成本文及来源/分析记录，随后按用户授权实施；最终结果见验收记录。`raw/`与既有`output/`不变。复核重点：范围交互表、选区限制、三个折叠入口是否符合实际阅读习惯。
